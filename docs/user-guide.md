# คู่มือผู้ใช้ Mimi

Mimi คือผู้ช่วย AI ส่วนตัว: คุยกับ agent, ตั้งเตือน, ทำ workflow อัตโนมัติ และเชื่อม Gmail/Outlook/ปฏิทินได้
ผู้ดูแลระบบจะให้ **ที่อยู่เซิร์ฟเวอร์**, **ชื่อผู้ใช้** และ **รหัสผ่าน** กับคุณ (สมัครเองไม่ได้)

## เริ่มใช้

| อุปกรณ์ | วิธี |
|---|---|
| เบราว์เซอร์ (ทุกเครื่อง) | เปิดที่อยู่เซิร์ฟเวอร์ แล้วเข้าสู่ระบบ |
| Android | เปิดด้วย Chrome → เข้าสู่ระบบ → เมนู ⋮ → **ติดตั้งแอป** |
| iPhone / iPad | เปิดด้วย Safari → แชร์ → **เพิ่มลงหน้าจอโฮม** (iOS 16.4 ขึ้นไปจึงรับแจ้งเตือนได้) |
| Mac | ติดตั้ง Mimi.app ที่ผู้ดูแลให้มา → ใส่ที่อยู่เซิร์ฟเวอร์ → เข้าสู่ระบบ (ไอคอน Mimi อยู่ที่แถบเมนูด้านบน) |

ครั้งแรก: ไปที่ **ตั้งค่า** แล้วเพิ่มผู้ให้บริการโมเดล (เช่น DeepSeek) ด้วย API key ของคุณเอง จากนั้นสร้าง agent ที่แท็บ **Agent**
หรือบอก **Overseer** เป็นภาษาธรรมดาว่าอยากได้ผู้ช่วยแบบไหน

## เครื่องที่ใช้ร่วมกับคนอื่น

- ตอนเข้าสู่ระบบ ติ๊ก **เครื่องนี้ไม่ใช่ของฉัน**: ปิดแท็บ/ปิดแอปแล้วต้องเข้าสู่ระบบใหม่ (แอป Mac ยกเลิกการเข้าสู่ระบบที่เซิร์ฟเวอร์ให้ด้วย)
- ใช้เสร็จ: **ตั้งค่า → บัญชี → ออกจากระบบ** เสมอ ระบบจะยกเลิกการเข้าสู่ระบบที่เซิร์ฟเวอร์ เลิกส่งแจ้งเตือนมาเครื่องนั้น และลบข้อมูลของ Mimi ในเครื่อง
- แอป Mac: เมนูไอคอน Mimi → **ออกจากระบบอัตโนมัติ** เลือก 5–60 นาทีที่ไม่ได้ใช้ (ล็อกหน้าจอเครื่องก็นับ)

## แจ้งเตือน

กดกระดิ่ง 🔔 → **เปิดแจ้งเตือนเครื่องนี้** → **ส่งทดสอบ** แต่ละเครื่องต้องเปิดเอง ข้อความเข้ารหัสจากเซิร์ฟเวอร์ถึงเครื่องคุณโดยตรง

## ให้ Mimi ใช้คอมพิวเตอร์ของคุณ (แอป Mac)

ปิดอยู่เป็นค่าเริ่มต้น เปิดที่เมนูไอคอน Mimi:
- **ให้ Mimi ใช้เครื่องนี้ (PC agent)**: agent อ่าน/เขียนไฟล์ได้เฉพาะ **โฟลเดอร์ที่อนุญาต** (เริ่มที่ `~/Mimi-Workspace`) และเปิดเบราว์เซอร์ของ agent เอง
- **อนุญาตให้รันคำสั่งบนเครื่องนี้ (shell)**: ให้ agent สั่งคำสั่ง/ปิดโปรแกรม/ปิดเครื่องได้ — มีสิทธิ์เท่าบัญชีผู้ใช้ของคุณบนเครื่องนี้ (ไม่จำกัดโฟลเดอร์) เปิดเฉพาะเมื่อจำเป็น
- ทุกอย่างที่เขียนไฟล์หรือรันคำสั่ง agent ต้องถามคุณในแชตก่อน กด **อนุญาต** เฉพาะเมื่อเข้าใจว่าจะทำอะไร
- ออกจากระบบ = ตัดการเชื่อมต่อทันที และลบโปรไฟล์เบราว์เซอร์ของ agent

## ข้อมูลของคุณอยู่ที่ไหน

- แชต ความจำ ไฟล์แนบ API key และการเชื่อม Google/Microsoft อยู่บนเซิร์ฟเวอร์ ใน "core" ที่แยกของคุณ ผู้ใช้คนอื่นเข้าไม่ได้
- **ผู้ดูแลระบบที่จัดการเซิร์ฟเวอร์เข้าถึงข้อมูลบนเซิร์ฟเวอร์ได้** อย่าเก็บสิ่งที่ไม่อยากให้ผู้ดูแลเห็น
- เครื่องของคุณเก็บแค่การเข้าสู่ระบบ (ถ้าไม่ได้ติ๊ก "เครื่องนี้ไม่ใช่ของฉัน") และการตั้งค่าหน้าจอเล็กน้อย
- สำรองข้อมูลเอง: **ตั้งค่า → สำรอง / กู้คืนข้อมูล → สำรองตอนนี้** แล้วดาวน์โหลด (ไฟล์มี API key ของคุณ เก็บให้ดี) เซิร์ฟเวอร์สำรองให้วันละครั้งด้วย

## ระวัง

- workflow หรือ tool ที่ได้มาจากคนอื่นหรือจากอินเทอร์เน็ต: โค้ดในนั้นถูกแยกไปรันในที่ปิด อ่านคีย์ของคุณไม่ได้ แต่ workflow ยังสั่ง agent ส่งเมล หรือเรียกเว็บแทนคุณได้ — อ่านดูก่อนเปิดใช้ และนำเข้าเฉพาะจากแหล่งที่ไว้ใจ
- ลิงก์ที่มีคนส่งมาให้ "เข้า Mimi" ที่มี `#token=` ต่อท้าย ระบบจะไม่ยอมเข้าสู่ระบบให้ — เข้าสู่ระบบด้วยชื่อผู้ใช้ของคุณเองเท่านั้น
- ลืมรหัสผ่าน / เครื่องหาย / เห็นอะไรผิดปกติ: แจ้งผู้ดูแลทันที (ผู้ดูแลสั่งออกจากระบบทุกเครื่องได้)

## จัดระเบียบไฟล์ (Task)

- พิมพ์ขอ เช่น "จัดระเบียบ Downloads ให้หน่อย" Mimi จะสแกนโฟลเดอร์แล้วแสดง **แผนก่อน** ว่ามีไฟล์กี่ไฟล์และจะย้ายไปโฟลเดอร์ไหน (Images, Documents, Audio, Video, Archives, Code, Installers, Other)
- ยังไม่มีการเปลี่ยนแปลงจนกว่าคุณจะกด **อนุญาตทั้งงานนี้** หรือ **อนุญาตครั้งนี้** ในแชต
- **อนุญาตทั้งงานนี้** ใช้ได้กับเครื่องมือกลุ่มเดียวกันตลอด task นี้ (มีอายุ 30 นาที) งานใหม่หรือแชตใหม่ต้องขออนุญาตใหม่
- ถ้าเครื่องที่รัน PC agent เปิด local consent ไว้ จะมีกล่องยืนยันบนเครื่องนั้นอีกชั้น (แอปเดสก์ท็อปแสดงเป็น dialog; โหมด headless ใช้ OS dialog) ถ้าไม่ตอบภายใน 15 นาทีจะถือว่าไม่อนุญาต
- Mimi **ไม่ลบไฟล์** — ย้ายเท่านั้น และข้ามไฟล์ซ่อน (ชื่อขึ้นต้นด้วย `.`), symlink และไฟล์ดาวน์โหลดที่ยังไม่เสร็จ (`.part`, `.crdownload`, `~$…` ฯลฯ)
- ค่าเริ่มต้นจัดการเฉพาะไฟล์ชั้นบนสุดของโฟลเดอร์ สูงสุด 500 ไฟล์ต่อรอบ และเมื่อชื่อปลายทางซ้ำจะเติม `(1)`, `(2)` ให้ (เลือก `skip` หรือ `overwrite` ได้)
- เมื่อเสร็จ การ์ด **ใบเสร็จ** ในแชตแสดงจำนวนไฟล์ที่ย้าย ตัวอย่างไฟล์ และปุ่ม **คืนไฟล์ทั้งหมด** ซึ่งย้ายทุกไฟล์กลับที่เดิม (ไฟล์ที่ชนกันจะถูกย้ายไปเก็บไว้ ไม่ลบ)
- ทุก task มี id, สถานะ และ receipt เก็บใน SQLite; journal สำหรับ undo อยู่ในโฟลเดอร์ `.mimi-organize` ของโฟลเดอร์นั้น

## งานโค้ดใน Workspace (Developer task)

- บอก Mimi ว่าอยากแก้ repo หรือโฟลเดอร์ไหน เช่น "แก้เทสต์ที่ fail ใน repo นี้ให้หน่อย"
- Mimi จะตรวจ git และหา test command (จาก `package.json`, `Cargo.toml`, `go.mod`, pytest หรือ `Makefile`) แล้วรันให้เห็นว่า fail ก่อน
- กด **อนุญาตทั้งงานนี้** ครั้งเดียว: Mimi จะ checkpoint, ให้ developer agent อ่าน/แก้ไฟล์ด้วย workspace tools, รันเทสต์ซ้ำ และแสดง diff
- Mimi **ไม่ commit / push / merge / publish** ใน workspace; คำสั่งเหล่านี้ถูกบล็อก
- ถ้าต้องใช้คำสั่งที่ทำลายข้อมูล (เช่น `rm -rf`) ต้องให้คุณอนุมัติ และ agent ต้องส่ง `allow_destructive`
- หลังแก้เสร็จ การ์ดใบเสร็จมีปุ่ม **คืนไฟล์ทั้งหมด** กลับไปที่ checkpoint; ไฟล์ที่เพิ่ม/แก้หลัง checkpoint จะถูกคัดลอกไป `.mimi-workspace/undo/` ก่อน ไม่ลบทิ้ง
- ถ้าโฟลเดอร์ยังไม่เป็น git repo Mimi จะ `git init` ให้ (โฟลเดอร์ต้องอยู่ใน allowed folders)

## คัดรูป (Photo cull)

- บอก Mimi ว่าอยากคัดรูปในโฟลเดอร์ไหน เช่น "คัดรูปซ้ำและรูปเบลอในโฟลเดอร์นี้ให้หน่อย"
- ต้องมี `ffmpeg` และ `ffprobe`; ถ้าไม่มี Mimi จะบอกชื่อโปรแกรมที่ขาดและวิธีติดตั้ง
- Mimi จะสแกนรูปซ้ำ (hash ตรงกันและ perceptual hash), คะแนนความเบลอ, วันที่/กล้องจาก EXIF แล้วแสดง **แผน** ก่อน
- ถ้าเปิด vision scoring จะสุ่มตรวจตามจำนวนที่กำหนดและไม่เกิน `max_cost_usd`; ค่าเริ่มต้นคือปิด (0 sample)
- เมื่อกดอนุญาต Mimi จะคัดลอกรูปที่เลือกไป `keep/` และรูปที่คัดออกไป `reject/` ในโฟลเดอร์ใหม่ (ค่าเริ่มต้น `<โฟลเดอร์>/culled`) — **ต้นฉบับไม่ถูกแก้หรือย้าย**
- Mimi จะทำ contact sheet ไว้ที่ `culled/preview/contact-sheet.jpg` (ถ้า ffmpeg ทำได้)
- ปุ่ม **คืนไฟล์ทั้งหมด** ในใบเสร็จจะย้ายไฟล์ผลลัพธ์ไป `.mimi-media/trash/` ไม่ลบทิ้ง; ต้นฉบับยังอยู่ครบ

## อัปโหลด YouTube

- บอก Mimi ว่าอยากอัปโหลดไฟล์ไหน พร้อมชื่อเรื่อง คำอธิบาย และการมองเห็น (private / unlisted / public)
- Mimi จะเปิด YouTube ในเบราว์เซอร์ของ agent; ถ้ายังไม่ล็อกอิน จะ **หยุดและขอให้คุณล็อกอินเอง** ในหน้าต่างนั้น (ไม่พิมพ์รหัสผ่าน/OTP/CAPTCHA แทนคุณ)
- หลังล็อกอินแล้วสั่งงานอีกครั้ง Mimi จะเลือกไฟล์ อัปโหลด กรอกข้อมูล และตรวจ URL
- ถ้าเลือก **public** จะมีคำขอยืนยันเพิ่มอีกครั้งก่อนกดเผยแพร่; unlisted/private ใช้การยืนยันครั้งแรก
- ไฟล์ต้นฉบับไม่ถูกแก้; ถ้าเป็นเพลง/เสียงอย่างเดียวและมีรูปปก Mimi จะ mux เป็น MP4 ให้ก่อนอัปโหลด (ต้องมี ffmpeg)
- หน้า YouTube อาจเปลี่ยนได้; ถ้า Mimi หาช่องไม่พบ จะบอกให้คุณช่วยกรอกในหน้าต่างเบราว์เซอร์

## ควบคุมแอปบนเดสก์ท็อป (Native layer)

- ใช้เมื่อแอปไม่มี API: `computer_observe`, `computer_click`, `computer_type`, `computer_key`, `computer_scroll`, `computer_app`, `computer_menu`, `computer_wait`, `computer_screenshot`, `computer_highlight`
- ต้องเปิด PC agent และกำหนด **รายชื่อแอปที่อนุญาต** ก่อน:
  - ค่าเริ่มต้นคือว่าง = ควบคุมแอปไม่ได้เลย
  - ค่าจาก environment: `MIMI_ALLOWED_APPS=Mail;Microsoft Outlook;Thunderbird` (คั่นด้วย `;`, ใช้ `*` เพื่ออนุญาตทั้งหมด)
  - แอปเดสก์ท็อป: ใส่ `pcAgent.apps` ใน `%APPDATA%\Mimi\config.json` (Windows) หรือ `~/Library/Application Support/Mimi/config.json` (macOS) แล้วเปิดแอปใหม่
- Mimi อ่าน accessibility tree และอ้างอิงด้วย ref จาก `computer_observe`; ต้อง observe ใหม่หลังหน้าเปลี่ยน
- **Mimi ไม่พิมพ์รหัสผ่าน/OTP ในช่อง secure** และไม่แก้ CAPTCHA/2FA/UAC; จะหยุดให้คุณทำเอง
- macOS: ต้องอนุญาต Accessibility, Screen Recording และ Automation ให้ Mimi ใน System Settings → Privacy & Security
- Windows: ควบคุมได้เฉพาะหน้าต่างระดับผู้ใช้ปกติ; หน้าต่าง elevated/UAC ต้องให้ผู้ใช้ทำเอง
- `computer_screenshot` / `computer_highlight` ส่งภาพเข้าห้องแชต; ภาพอาจมีข้อมูลลับบนจอ
- **Mail POP3 recipe**: ช่วยตั้งค่า Apple Mail / Outlook / Thunderbird — เติมชื่อ อีเมล เซิร์ฟเวอร์/พอร์ตให้، คุณพิมพ์รหัสผ่านเอง، ทดสอบการเชื่อมต่อ และส่งเมลทดสอบเมื่อยืนยัน

## งานเบื้องหลัง / Audit (Autonomy)

- งานแบบ background ต้องเปิด opt-in: `MIMI_ALLOW_BACKGROUND_TASKS=1` และ agent ต้องส่ง `background: true`; Mimi จะแจ้งผลใน inbox เมื่อจบ
- งานที่ถูก interrupt ตอน core restart จะถูกทำเป็น `paused`; ใช้ `task_resume` กับ recipe ที่ resume ได้ (file-organizer, photo-cull) หรือเริ่มงานใหม่
- `task_list` ดูงานล่าสุด, `task_audit` export JSONL (หนึ่ง task ต่อบรรทัด), `task_kill` หยุดทุกงานที่กำลังรัน
- งบประมาณรายวันและ budget ของแต่ละ run ยังใช้กับงาน background; ไม่มี telemetry โดยค่าเริ่มต้น
- **หมายเหตุ**: การตั้งเวลา background ใช้ trigger/workflow ที่มีอยู่ แล้วให้ agent เรียก `task_run` ด้วย `background: true`
